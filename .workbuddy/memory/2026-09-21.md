## 独占模式卡顿排查（用户实机日志 + 代码审查）

**背景**：用户在别的会话改了一轮（未提交，工作区 5 个文件 diff），想修独占模式播放卡顿，无效。

**根因链（已用日志 + 代码 + MSDN 三方印证）**：
1. 上次主修「周期 10ms < 缓冲 100ms」在独占模式下必然失败：MSDN 规定独占+事件驱动时
   hnsPeriodicity 必须等于 hnsBufferDuration，Initialize 直接拒绝 → 代码静默退回周期=缓冲=100ms。
   日志铁证：每首 `WASAPI独占协商 ... [周期=缓冲100ms]`（DescribePeriod 的 smallPeriod=false 分支）。
   → 修复从未生效，"设备缓冲保有 90ms 存货"的前提在独占模式不成立。
2. 独占模式周期=缓冲=100ms：每个渲染事件到来时设备缓冲已啃光，渲染线程干多少活
   （读盘/DSP/GC/等锁）设备就静默多久。日志 `[源诊断] 读源耗时尖峰=15-16ms` 即间隙来源。
3. 读源慢的具体来源：
   - >64MB 的缓存 WAV（96kHz/24bit 曲目，缓存目录 23 个里 8 个）走流式读取，渲染线程真读盘；
   - ≤64MB 虽整读进内存，但预载下一首时 UI 线程同步 ReadAllBytes（≤64MB）→ LOH 分配 →
     gen2 GC → 渲染线程被暂停（即使当前曲全在内存里也中招，见 23:08:32.088 尖峰 nextMount=False）；
   - TrimCache 一次删一半（实测 21 个文件/958MB）与播放抢 I/O；
   - 音乐源在 D:\天翼云盘同步盘（云同步盘），eCloud 客户端 I/O 竞争。
4. 缓存目录 C:\Users\admin\AppData\Local\CelesteMusicPlayer\TranscodeCache（上限 2GB）。

**架构结论（本次全部读码确认）**：
- HiFi 三模式（共享/独占/ASIO）共用躯干：源文件 → ffmpeg 转码 WAV 缓存 → OpenWaveSource
  （≤64MB 整读内存 / >64MB 8MB 流式）→ SeamlessWaveProvider（无缝+交叉淡化）→（独占）SRC 升频
  → 多声道降混 → ManagedDspSourceProvider（DSP 链，全关=bit-perfect 直通）→ 三个输出分支。
- IsHiFiMode 恒 true，AudioGraph/MediaPlayer 旧路径已死代码。
- 无缝：同格式（率/位深/声道全同）才字节级续接；格式不同 → 不采纳 → 重建会话有间隙。
- 音量：HiFi+软音量开=DSP 采样级增益（设备音量钉 100%）；软音量关=设备端点音量(v²)；
  共享=DSP 增益；DSD/DoP=软音量无效只能调设备。
- AB 点循环：不存在（无任何代码），未来要做需碰 Position 计时 + SeekTo（render 线程安全 seek 已支持）。
- 内存泄露史：曾无条件整首 ReadAllBytes + 预载双份 → 2-3GB → 已修（64MB 分流 + 流式 + FileShare.Delete）；
  另一处 ListView 多选泄漏已修（f8e7b3a，UI 层）。

**修复方向（已向用户提案，未获批准前不动代码）**：

   字节不变 → bit-perfect 不受影响；独占模式唯一正解。
B. 预载读盘移出 UI 线程；TrimCache 限量删除/播放中不删。

## ECHO 源码调研 + 四阶段修复路线（本轮，用户未批准，未动代码）

用户提供了 ECHO 播放器源码 `C:/Users/admin/Downloads/Download/ECHO-main`（Electron + Rust/C++ native），
要求对比 ECHO 方案并给修复路线。两个 Explore 子代理并行调研，结论已写入
`ECHO方案对比与修复路线-2026-09-21.md`（工作区根目录）。

**ECHO 核心设计（证据充分）**：
- 音频全在独立 daemon 进程（JSON-RPC over fd3/fd4 管道 + 5s 心跳），UI 崩不拖垮播放；
  但**当前发货路径只有 WASAPI Shared**（miniaudio），独占/ASIO 代码写了没接线（DaemonAudioBackend.ts:12 exclusiveMode:false）——别照抄其独占实现。
- 设备回调只 memcpy 环形缓冲；解码线程 4096 帧/块流式 push + 背压；常备 ~184ms 存货；
  回调抢锁用 try_lock，拿不到就输出静音计数（PcmRingAudioSource.cpp:218-224）——实时线程永不阻塞。
- **无 PCM 落盘缓存**：libav 流式直解（swresample 内建重采样）或 ffmpeg CLI 管道 `-f f32le pipe:1`。
- seek = 解 0.25s prime + FIFO 原子替换 + 后台续推（AudioDaemon.cpp:389-521）。
- 预载下一首只解前 1 秒内存缓存（AudioDaemon.cpp:539-591）。
- DSP 全关 return 旁路；参数原子量/RPC 更新；音量数字增益不动端点音量。

**Celeste 侧新确认（上一轮假设的修正，都带 file:line）**：
- MP3 卡顿与大小无关，主因排序：① `[周期=缓冲100ms]` 回退；② **每次起播 UI 线程同步 ffmpeg 探测**（FfmpegDecoderBackend.cs:425-427，最坏冻 3s）；③ 预加载再跑一次同步探测 + 整轨转码 + **≤64MB ReadAllBytes 在 UI 线程**（Playback3.cs:2716,2724）；④ 起播同时跑两个 ffmpeg（转码+波形，波形进程 Normal 优先级且逐块回 UI）；⑤ gen2/LOH GC 暂停渲染线程。
- MP3 首次播放同样整轨转码落盘才开播（TranscodeToWavAsync 无格式白名单检查）。
- TranscodeCache 无用户清理入口（WebDavCache 有按钮可照抄：SettingsWindow.xaml:1736）。
- seek/歌词确认健康（pending 标志位/无锁属性），但每次 seek 后触发 UI 线程预加载。
- DSP 全关时仍在做电平+频谱（PlayWavAsync:687,690 默认开），白干 CPU。
- GC 无调优（无 ServerGC/TPGO/LOH 压缩）。
