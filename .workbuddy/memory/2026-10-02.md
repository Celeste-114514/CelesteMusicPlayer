## 前端自由度调研（产出 outputs/前端自由度方案-三层皮肤架构-2026-10-02.html）
用户焦虑：觉得被 WinUI 框死，羡慕 ECHO（Electron）的自定义程度，想要"WinUI 只是一个预设皮肤"。

### ★★ 决定性实测数据（推翻"被框死"的判断）
扫全部 **21 个 XAML / 13,306 行**：整个程序只引用 **25 个不同的系统主题刷子，共 370 处**；
XAML 里硬编码颜色只有 **8 处**（全在 SettingsWindow.xaml）。
Top5：`CardStrokeColorDefaultBrush` 126、`CardBackgroundFillColorDefaultBrush` 64、
`SubtleFillColorSecondaryBrush` 31、`TextFillColorPrimaryBrush` 20、`AccentFillColorSecondaryBrush` 19。
→ **"WinUI 味"的根源 = UI 直接引用 WinUI 系统刷子，其值由系统决定，我们只覆盖了 accent 一小部分。**
→ **只要重定义这 25 个键的值，370 处引用自动全变**（ResourceDictionary 覆盖 ≡ ECHO 的 CSS 变量覆盖）。
**结论：没被 C#/WinUI 框死，卡的是"皮肤写在代码里、不是数据"。这个病换任何框架都复发。**

### ECHO 自由度真相（不来自 Electron，三层 + 一个约束）
1 语义令牌：`tokens.css` **739 个 CSS 变量**，UI 只准引用 `--theme-*` 语义名；
2 主题文件：`echo-next.custom-theme` JSON（schema/version/basePreset/**light+dark 两组**/21+ 预设），可导入导出；
3 生态：ThemeCustomEditor + CustomThemeLibrary + **THEME_AI_GUIDE.md（给 AI 读的规范，AI 直接生成主题 JSON）**
   + 插件可贡献预设 + Steam 创意工坊；
约束：`check:theme-colors` 挂进 lint，新 CSS 出现硬编码颜色**构建失败**，旧代码有 `theme-color-baseline.json` 只降不升。
**最值钱的是第 3 层的"AI 可生成 + 可导入导出"，与技术栈无关，现在就能有。**

## ★ 第 0 步 WebView2 实测结果（2026-10-02 完成，报告 `outputs/WebView2第0步验证结果-2026-10-02.html`）
探针工程 `tools/WebView2Probe`（WinForms 宿主 + net9.0-windows，独立 global.json 钉 SDK 9，
包 `Microsoft.Web.WebView2`）。**主工程零改动**。运行方式：沙箱 apphost 被 Low IL 挡 → 用
`dotnet exec WebView2Probe.dll`；结果同时写 `_wv2_probe_out.txt`（Say() 每步即落盘，防命令超时丢结果）。
- 环境：Runtime **154.0.4258.48**（Evergreen 已装），Win11 26200，SDK 9.0.317。
- **实测数字**：初始化 **226/264/414ms**；首次渲染 4KB HTML **16–19ms**；
  **CSS 变量注入 avg 0.42–0.51ms 且即时生效**（主题热切换前提成立）；
  ExecuteScriptAsync 往返 **avg 0.16ms**；JS→C# 上行 50 条合计 **0.5ms**；C#→JS 下行 avg **0.14ms**；
  切页重绘 avg **0.32–0.83ms**。→ 通信/渲染/换肤全部不是瓶颈。
- **⚠ 内存实测推翻此前估值**：第一实例合计 **≈286MB**（宿主仅 10.4MB，大头是子进程 276MB/6 个：
  browser+GPU+renderer）；**第二实例仅 ≈62MB、初始化 26.7ms** → 证明 286MB 是一次性固定成本。
  **结论：常驻单实例 + 前端路由是唯一正解（十几个页面各起一个 = 1GB+）**。
  以前说的"单实例 80~150MB"是错的，以后按 286MB 讲。
- **坑1（必记）**：`PostWebMessageAsJson` 往返 **50/50 全失败** —— JS 原样回传 JSON 对象时
  C# `TryGetWebMessageAsString()` 读不出字符串。**业务消息一律走 `PostWebMessageAsString` 传字符串 JSON**，
  C# 侧自己反序列化（`PostWebMessageAsString` 实测单条 1.3ms 正常）。
- **坑2**：本机 WebView2 进程堆积到 700MB+ 时，构建会报 NuGet `OutOfMemoryException` / csc `0xC0000005`
  → `dotnet build-server shutdown` + `--no-restore -m:1` 重来即通（本机已知 flake，非代码问题）。
- 探针第 3 步红绿交替 30 次在几十毫秒内跑完、最后停在绿色 → **用户看到"一片绿"是预期行为不是卡死**。
