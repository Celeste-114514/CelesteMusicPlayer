# v26.10.3 发布（提交 341c46f + 781ace8 + 65ceb34，tag v26.10.3）

## 托盘右键菜单滚动条根因（实证闭环）

- **根因**：H.NotifyIcon 2.3.0 SecondWindow 模式弹菜单前调 `MeasureFlyout` 做**冷测量**
  （菜单项还没套模板）。`MenuFlyoutSeparator` 什么都没钉，实测 `DesiredSize=(0,0)`，
  而真正渲染占 **3px**（WinUI 默认模板：1px 线 + 上下 Padding 各 1px）。窗口高公式
  `round(scale×(4+Σ)+4)`：修复前 Σ=224 → 窗口 232px，内容实需 236px → 滚动条；
  钉 `Height=3` 后 Σ=230 → 窗口 238px ≥ 236px → 消失。**上游 master/2.4.1 均未修**。
- **实证手法**：App 内临时探针（`CELESTE_TRAY_DEBUG=1`，6s 延时弹菜单 + 打每项
  DesiredSize）+ EnumWindows 转储本进程窗口矩形（UIA 采不到透明第二窗口时的兜底）。
  库的 `TaskbarIcon.ShowContextMenu(Point)` 公开，可绕过鼠标注入直接弹菜单。
  验证后探针全拆（grep 残留=0）。
- **修复**：`TrayMenuBuilder.Separator()` 钉 `Height=3`。

## 发版链路（用户批准「发布新版本」后）

- **隐藏皮肤入口**（781ace8）：MainWindow.xaml 三个 pill 入口整段注释（代码一行没删，
  注释里写明恢复方法）；csproj 4 个 WebUI Content 行整块注释；版本 26.10.3.0 四处
  （Version/AssemblyVersion/FileVersion/appxmanifest）。
- **⚠ publish 目录污染事故（本轮最大教训）**：fd publish 重试（dist\publish-fd）会
  顺手更新 `bin\Release\...\win-x64\publish` 里的 exe/dll/pri——**fd 与 sc 不能假定
  共用中间目录后输出还干净**。更坑的是 `dist/publish-sc` 快照的文件 mtime 被保留
  （16:07），肉眼看着像当天新复制，实际是 **26.10.2.0 旧货**——冒烟一跑标题
  v26.10.2.0、皮肤入口残留 2 个当场现形。**铁律：任何 publish 快照交付/打包前必须
  冒烟验版本号，mtime 和 md5 都说明不了「是不是这一版」**。最终重跑
  `_build_release_sc.py`（attempt 1 Roslyn 0xC0000005 flake、attempt 2 过）重出 sc，

- **GitHub Release**（id 409564028）：**本机没有 gh CLI**——用 curl + `git credential

  照 v26.10.2 模式：版本号+README 一个 commit 再打附注 tag）。对外口径只讲托盘
