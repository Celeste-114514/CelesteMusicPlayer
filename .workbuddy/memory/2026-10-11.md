# v26.10.3 发布（提交 341c46f + 781ace8 + 65ceb34，tag v26.10.3）

## 托盘右键菜单滚动条根因（实证闭环）

- **根因**：H.NotifyIcon 2.3.0 SecondWindow 模式弹菜单前调 `MeasureFlyout` 做**冷测量**
  （菜单项还没套模板）。`MenuFlyoutSeparator` 什么都没钉，实测 `DesiredSize=(0,0)`，
  而真正渲染占 **3px**（WinUI 默认模板：1px 线 + 上下 Padding 各 1px）。窗口高公式
  `round(scale×(4+Σ)+4)`：修复前 Σ=224 → 窗口 232px，内容实需 236px → 滚动条；
  钉 `Height=3` 后 Σ=230 → 窗口 238px ≥ 236px → 消失。**上游 master/2.4.1 均未修**。
- **实证手法**：App 内临时探针（`CELESTE_TRAY_DEBUG=1`，6s 延时弹菜单 + 打每项
  DesiredSize）+ EnumWindows 转储本进程窗口矩形（UIA 采不到透明第二窗口时的兜底）。
  库的 `TaskbarIcon.ShowContextMenu(Point)` 公开，可绕过鼠标注入直接弹菜单。
  验证后探针全拆（grep 残留=0）。
- **修复**：`TrayMenuBuilder.Separator()` 钉 `Height=3`。

## 发版链路（用户批准「发布新版本」后）

- **隐藏皮肤入口**（781ace8）：MainWindow.xaml 三个 pill 入口整段注释（代码一行没删，
  注释里写明恢复方法）；csproj 4 个 WebUI Content 行整块注释；版本 26.10.3.0 四处
  （Version/AssemblyVersion/FileVersion/appxmanifest）。
- **⚠ publish 目录污染事故（本轮最大教训）**：fd publish 重试（dist\publish-fd）会
  顺手更新 `bin\Release\...\win-x64\publish` 里的 exe/dll/pri——**fd 与 sc 不能假定
  共用中间目录后输出还干净**。更坑的是 `dist/publish-sc` 快照的文件 mtime 被保留
  （16:07），肉眼看着像当天新复制，实际是 **26.10.2.0 旧货**——冒烟一跑标题
  v26.10.2.0、皮肤入口残留 2 个当场现形。**铁律：任何 publish 快照交付/打包前必须
  冒烟验版本号，mtime 和 md5 都说明不了「是不是这一版」**。最终重跑
  `_build_release_sc.py`（attempt 1 Roslyn 0xC0000005 flake、attempt 2 过）重出 sc，
  stage（625 文件全量 md5 STAGE_BAD=0）→ deliver（FINAL_BAD=0）→ IL 复验 OK →
  run-latest 冒烟 FINAL=SMOKE_OK。
- **makensis flake**：`compress() failed [-4]` exit=-1073741819 环境崩（installer
  脚本自 v26.10.2 零变更），重跑一次即过。产物 fd 24.3MB / sc 95.5MB，与上版体积吻合。
- **GitHub Release**（id 409564028）：**本机没有 gh CLI**——用 curl + `git credential
  fill` 拿 token 直调 API。坑：`target_commitish` 传短 SHA 报 422 invalid，tag 已推
  远程时干脆不传该字段。两步法：先建（make_latest=false）→ 上传 3 资产 → PATCH
  latest=true。上传走 uploads.github.com，直连即可（不走代理）。
- **README/release notes**：`### v26.10.3（2026-10-11）` 条目单独 commit（65ceb34，
  照 v26.10.2 模式：版本号+README 一个 commit 再打附注 tag）。对外口径只讲托盘
  滚动条修复 + 皮肤试点入口暂时下架（v26.10.2..HEAD 间多数皮肤提交已整体隐藏）。

# 外观设置：emoji 分类图标开关 + 播放队列换图标（提交 b1b6f01）

## 需求与实现

- **开关**（外观设置页，「界面风格」下方）：`启用 emoji 分类图标`。关（默认）= 侧栏
  16 个分类用纯色 Fluent 字形（与图景同一套，字形跟随文字单色，不涂类别彩色）；
  开 = 彩色 emoji。**经典（浅色/深色/跟随系统）与图景都按开关走；极客皮肤不读这个
  开关**（ApplyNavIconStyle 里 `emojiOn = settings.NavEmojiIcons && !IsGeekUiStyleActive()`）。
- **字段** `AppSettingsState.NavEmojiIcons`（默认 false；老存档 JSON 缺字段即 false）。
  设置页 ToggleSwitch 走统一 `SettingToggle_Toggled` → `MainWindow.ApplySettingsLive`
  → `ApplyUiStyleMode` → `ApplyNavIconStyle/ApplyClassicNavIconColors` 当场刷新，不用重启。
- **播放队列图标**：侧栏/播放状态栏/迷你播放器三处 RedEye(E7B3) → **List(EA37)**
  （用户指出眼睛不像播放队列）。换字形前先解析 segmdl2.ttf 的 cmap format 4 验证
  codepoint 存在，免得出豆腐块。

## UIA 验证经验（本轮两个新结论）

- **Collapsed 元素不在 UIA 树里**：「按钮里找不到 emoji 文本」不是失败，正是隐藏的
  通过信号。判定显隐要「全局扫描 TextControl + IsOffscreen」，别按「元素应在树里」写断言。
- 侧栏 16 个分类里 UIA 只能稳定采到 13 个（流派/年份/网络音乐库在侧栏滚动区外采不到），
  所以验证从「逐按钮比对」改成「全窗口 emoji 扫描」：关=0 可见、开=13 可见、两态点击
  导航均正常（EMOJI_TOGGLE_OK）。冒烟 SMOKE_OK。
