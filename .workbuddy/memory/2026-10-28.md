## Git 索引损坏修复（方案第 0 步）
现象：`git status` 报 `index file corrupt`（签名 0x00000000），`git branch` 报无法解析 HEAD。
根因：本机"文件前 4096 字节被清零"的老毛病命中了 `.git` 元数据两处：
- `.git/refs/heads/main` 41 字节全零（0000...）→ HEAD 解不出分支
- `.git/index` 头部全零

处置顺序（备份先行，未盲删 index）：
1. 元数据备份到 **`C:\Users\MSI\source\repos\_celeste-git-backup-20261028-0123\metadata\`（387K，仓库外）**
2. 扫所有 commit 对象 + 工作区 386 个源文件 → **源码零损坏**，只有元数据坏了
3. **关键：reflog 停在 10-27 17:20，但今天 00:00 后有 58 个对象动过** → 找出被吞掉的提交
   `b5510e94 feat: make web UI primary, unify window chrome...`（10-28 00:59）
   验证链：parent = reflog 末条 `4bea9c15`；origin/main `ab16c1e9` 是其祖先 → 确认它就是 main 应有的指向
4. 回写 refs/heads/main = b5510e94；删坏 index 后 `git read-tree HEAD` 重建（**不是 reset --hard，工作区未动**）
5. 结果：log/status/fsck 全部正常，main 领先 origin/main 67 个提交，改动清单只有 10 个已改 + 未跟踪临时文件

⚠ 教训：ref 文件被零填充时 reflog 也可能停在更旧的提交上；**修复前必须按 mtime 找今天新增的 commit 对象**，
否则会误把 main 指回旧提交，丢掉当天的工作。

## 拖动"很卡、不跟手、帧率也不够"的修复
两个原因叠加，只改轮询频率治不好：
1. **每帧 `AppWindow.Move()` 太重**（要绕 XAML→AppWindow→窗口服务）。改法：
   优先 把 `WM_NCLBUTTONDOWN`(HTCAPTION) 丢给系统跑它自己的**模态移动循环**（零轮询、UI 线程不参与、最跟手）；
   不放心它一定生效，所以挂一个 60ms 探针看窗口有没有跟着动，**没动就自动回落**到 8ms 的 `SetWindowPos` 直调。
   （发之前必须 `ReleaseCapture()` —— 光标可能被 WebView2 捕获着，系统进不了自己的移动循环。）
2. **隐藏的主窗口还在满速干活**：`MainWindow.LevelMeter` 33ms 一次读电平、改矩形，给一个没人看的窗口画图，
   既挤掉拖动的轮询，也把整体帧率拉低（用户口述"帧率也不够"正对应这个）。加了 `if (!AppWindow.IsVisible) return;` 门禁。
   → **通用教训**：网页外壳接管界面后，旧 MainWindow 的视觉定时器全是净亏损，以后见到就先问"这个还看得见吗"。

## ⚠ 伪拖动 bug（"点一下，之后不按住也能拖着窗口跑"）——务必记住这个坑
根因：**网页 pointerdown → 宿主要跨一次 IPC（几十毫秒级）**。宿主收到时物理按键可能早就松开了，
此时照发 `WM_NCLBUTTONDOWN(HTCAPTION)`，系统会误以为键还按着而进入自己的模态移动循环
→ 变成"不用按住也能拖"，只有再点一下才退出。用户原话："单击区域以后拖动？这逻辑太奇怪了"。

修法两条，都已落地在 `WebShellWindow`：
1. **判定要看真实按键状态，不看消息到达时间**：`StartWindowDrag` 和 `TryNativeMoveLoop` 里各查一次
   `GetAsyncKeyState(VK_LBUTTON)`，松了就直接 return（那只是普通单击，本来就不该拖）。
2. **自愈**：探针里若发现"按键已松但 `GetCapture()==本窗口`"，说明真有一个没人按住的循环卡住了，
   补发一条 `WM_LBUTTONUP` 让系统自己把循环收掉。
→ 通用于所有「网页那边触发宿主去合成 Windows 非客户区消息（移动/改大小）」的场景：
发这类消息之前一律先核对物理按键状态。

## 更新检查给出明确结论（W2，3407411）
- `UpdateChecker` 以前只有 `UpdateInfo?`：null 既可能是"已是最新"也可能是"断网"，设置页一律显示"已经是最新版"
  → 断网时骗用户。现在返回 `UpdateCheckResult`：`UpToDate / Available / UnsupportedPackage / Failed`，
  失败带 `ErrorCategory`（network/timeout/http/rate-limit/json/version-parse）与 `CheckedAt`。
- ⚠ **失败不清 `LatestAvailable`**，只有服务端明确"没有更新"才清。失败结果带 `LastKnownUpdate`，
  网页据此说"上次检查发现过 X"。
- ⚠ 版本号只认 **3~4 段日期式**（`26.9`、`nightly` 直接 version-parse 失败，不再退化成 0 去比）。
  同号下 正式版 > 预览版，`beta.2 > beta.1`，`rc1 > beta.9`。稳定通道遇到预览版 → 状态仍是"已是最新"
  但 `PrereleaseIgnored=true`，界面要说"发现预览版但不自动升级"。
- ⚠ 选包**严格按** `CelesteMusicPlayer-Setup[-SC][-x64|arm64]-<ver>.exe`：应用名 + Setup 段都要对上，
  **删掉了"任意 .exe 兜底"**（那个兜底会让 sc 用户下 fd 包或别的程序）；Portable/7z/zip 一律不认。
- ⚠ 哈希清单：请求走同一份 15s 预算（清单自己 5s，超时只影响"能否校验"、不把已有新版本判成失败）；
  解析要 **64 位十六进制 + 精确文件名**，支持 `hash␠␠name` 与 `hash␠*name`。
  `UpdateChecksumState` 三态：Verified / Unpublished / Unverifiable。
