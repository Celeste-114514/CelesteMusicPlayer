- 用户报「DSP 面板声道矩阵可视化坏了，应该是个圆」→ 自纠「没坏，只是 L/R 字母不在正中心」。

  1. 上一轮增量发布把 run-latest 里某个原生 DLL 拷坏 → 启动前无日志的 0xC0000005 静默退（**不是源码问题**：撤掉我的改动重发照样崩，而旧好备份能启动，坐定是坏文件）。

## 01:4x 紧急：GitHub release 自包含包「打不开」排查（已定位根因）
- 现象：用户下载 GitHub v26.10.11 的 `Setup-SC`（自包含）装完打不开；把**本地 dist 那份**发给他就能用。
- **根因不是包坏了，是云端那份根本不是本地这份**：`.github/workflows/ci.yml` 在 tag 时用 `tools/package-installers.ps1` 现场打包并 `gh release upload --clobber`，
  所以 Release 上的资产 = GitHub Actions runner 产物（云端 SUMS 与云端 exe 自洽：`0f3de27d…`/95,295,455；本地是 `89e4162…`/95,478,059）。
- **两份包内容 diff（7z 解开对比）**：文件数都是 629，但
  - `CelesteMusicPlayer.pri` 云端 **253,000** vs 本地 **1,601,192** → 云端 XAML 资源整批缺失（这就是启动即失败的原因）；
  - 运行时版本不同（云端 mscordaccore 9.0.20x / 本地 9.0.19x），100+ 个 System.* dll 各差 40B；
  - exe 都是 303,104（自包含尺寸正常），所以**光看 exe/哈希/能否安装都发现不了**。
- **真凶**：`package-installers.ps1` 的 publish 命令**漏了 `-p:Platform=x64` 和 `-p:WindowsPackageType=None`**（本地手工发布命令一直带）。
  走 MSIX 路径时 .pri 只生成约 253KB。
- 已修脚本：两个 publish 都补齐 `-p:Platform=x64 -p:WindowsPackageType=None [-p:CelesteSelfContainedDistribute=true] -p:EnableSourceControlManagerQueries=false`；

- 排查手法备忘：① `curl https://api.github.com/repos/<owner>/<repo>/releases/latest` 拿资产真实 size 与本地比对（最快发现"上传的不是本地那份"）；
