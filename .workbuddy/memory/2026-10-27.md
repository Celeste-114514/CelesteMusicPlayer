### 根因
底栏背景写死在 `transport.css` 的 `.player{background:rgba(255,252,253,.88)}` ——
一条固定浅白，任何主题都盖不住。同一批还有三个漏点：
- `.order-menu`（底栏上的播放顺序菜单）`background:#fffafdf5`
- `.orbit-dialog`（左栏轨道弹层）`#fff` 描边 + `#fdfbf9f5` 底
- `waveform.js` 进度波形硬编码 `#dfd5dc`（未播放）/ `#e66b96`（已播放），深色下一条亮带

### 做了什么
- **逐页去硬编码（约 470 处，14 个 CSS）**：navigation / transport / transport-panels / songs /
  library / collections / home / folders / track-menu / audio-chain / tags / settings / shell / corner。
  分类规则：浅灰底→`--panel`、浅粉底→`--accent-soft`、灰紫字→`--muted`、深字→`--ink`、
  粉红系→`--accent`；金/绿/蓝装饰色与 **DSP 功能性配色一律不动**（曲线/频谱刷成强调色就废了）。
  实现脚本留在仓库根 `_theme_var_sweep.py`（按 HLS 亮度+色相分类，可直接复用）。
- **底栏接主题**：`.player` 改 `color-mix(in srgb, var(--player-bg) calc(var(--player-opacity)*100%), transparent)`；
  `--player-bg` 在 `theme.css` 里定义成 **`color-mix(in srgb, var(--shell) 88%, var(--surface))`** ——
  不单独存值，否则用户改外壳色时底栏留旧值，又是"半截没变"。比 shell 略亮，保留原来"浮起来"的层次。
- **底栏可调**：`--player-opacity`（默认 .88）/`--player-blur`（默认 0px，毛玻璃要持续重绘，默认关）/
  `--cover-radius`（radius×0.46）/`--cover-size`（默认 62px）。外观页里单独成组
  「底栏（播放状态栏）」，按 id 前缀 `player-|cover-` 从元素细调里分出来。
- **波形**：`wave-idle` / `wave-played` 进 `VarNames` 由 C# 派生；`waveform.js` 读 CSS 变量 +
  监听 `celeste:theme-applied` 重读色板。canvas 拿不到 CSS 变量，必须自己取色并重绘。
- **`color-scheme`**：`theme.css` 加 `:root[data-theme="dark"]{color-scheme:dark}`。
  滚动条 / range 轨道 / select 这些是浏览器原生绘制，CSS 变量管不到，只有它能影响。

### 顺手修掉的真 bug
`MainWindow.WebAppearance.cs` 的 `Get(key)`：override 里存的是 `"70px"`，
`double.TryParse("70px")` 必然失败 → 滑杆回弹到预设值（实际生效值是对的）。
所有带 px 的参数（radius/blur/cover-*）都受影响，看着像"改了没存上"。现在先剥单位再解析。
