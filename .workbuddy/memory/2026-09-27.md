## 产品方向咨询：UI 要不要重构 / 要不要换 Electron / 要不要做推广视频

用户提出三个纠结：① 界面被说"花"，想重构外观但不想丢 WinUI；② Echo 用 Electron 外壳 + C++ 内核，自己不想用但受影响；③ 苦于没用户反馈，想先做推广视频换反馈。

**给出的结论（未改任何代码，纯咨询）**：
- **不换 Electron**：核心资产是 WASAPI 独占 / ASIO / DSD DoP / bit-perfect，全是 Windows 原生 API，C# 零距离调用。换壳 = UI 全重写 + 音频层加桥，代价几周 + 内存翻倍 + HiFi 用户观感减分。
- **不整体重构外观**：真问题不是 UI 好不好看，是没人用。没用户时重构 = 闭门造车。
- **先拿反馈再改**，但顺序是先定向社区后做视频（视频是放大器不是起点）。

**WinUI 能否做出"不像 WinUI"的前端 —— 结论：能，框架不是天花板，默认样式才是。**
自由度量级：ControlTemplate 可完全重写任何控件；窗口外壳可自绘标题栏/隐藏边框（AppWindow，SDK 1.8 支持）；Mica/Acrylic 可关；Win2D + Composition API 可自绘任意 2D 与动画（原生性能，优于 Electron）。
真边界只有：跨平台（本项目用不上）、Web 生态组件库、极复杂文本排版。

## 设置窗口：顶部搜索框（f3e0daa）
- 需求：几百个设置项散在 10 个分类里，找一个开关要逐个翻。
- 结构：NavigationView + 10 个 `PanelXxx` ScrollViewer；内容 Grid 加 RowDefinitions，
  Row0 = AutoSuggestBox（+ 右侧计数 TextBlock），Row1 = 包一层 Grid 装原面板。
- **搜索实现（不改 XAML 里几百个设置项的关键）**：运行时遍历面板视觉树——
  竖向 StackPanel = 分组容器（逐个子项决定去留）；Grid 两列行 = 一个完整设置项
  （整行一起留/藏）；Border/ScrollViewer = 外壳穿透。命中行的紧邻上方小标题
  （TextBlock FontSize>=14）自动保留，否则设置行悬空没头。
- 可见性按元素记录原始值（Dictionary<FrameworkElement,Visibility>），清空关键词完整还原，
  含本来就 Collapsed 的条件项。面板 ScrollViewer 自身可见性不动（归导航切换管），
  只过滤它的子节点。
- 导航项显示各分类命中数「外观设置 (3)」，清空还原；首次命中自动跳分类
  （ShowPanel + SettingsNav.SelectedItem）；建议列表 15 条「标题 · 分类名」，
  选中后跳分类 + StartBringIntoView。
- **两个坑**：
  1. WinUI3 枚举名是 `AutoSuggestionBoxTextChangeReason`（不是 AutoSuggestBox...），否则 CS0103。
  2. 子节点必须去重：`VisualTreeHelper.GetChild` 与 `ContentControl.Content` 会给到同一节点，
     不去重则命中项重复计数、建议列表出现重复项；用
     `new HashSet<DependencyObject>(ReferenceEqualityComparer.Instance)` 去重。
     文本计算走 `_searchTextCache` 按节点缓存，避免 O(n²)。
- 构建：Debug 第 1 次因枚举名报错 + 两次环境性 MSB3073；改名后一次过；
  Release publish 26s 过；dist\run-latest 85 文件 REPAIRED=7 FINAL_BAD=0。
