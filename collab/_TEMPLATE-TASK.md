# 任务单模板 — 复制这个改，不要从空白开始

> 用法：复制成 `TASK-YYYYMMDD-短名.md`，填完之后连同 `LOCK.md`（改成持有方: Codex）一起交给 Codex。
> **"我已经排查过的"那一节最重要** —— 不填它，Codex 就会把你已经烧过的钱再烧一遍。

---

```markdown
# TASK-2026-10-26-示例短名

## 1. 一句话目标
（要达成什么。不要写背景故事。）

## 2. 我（WorkBuddy）已经排查过的 —— 别重复做
- 读了 `文件:行号范围`，结论：……
- grep 过关键词 `xxx`，命中范围：`A.cs:123`、`B.cs:456`，排除：……
- 试过方案 X，结果：……（附关键日志行，不要粘整份日志）
- 已排除的可能性：……
- 环境事实：构建配置 = Release/x64，日志在 logs/app 与 logs/audio 两处

## 3. 相关代码（给坐标，不给全文）
### 文件 A：`CelesteMusicPlayer/XXX.cs`
行 120-160：
​```csharp
（贴这几十行就够，别贴整个文件）
​```

### 文件 B：`CelesteMusicPlayer/YYY.xaml`
行 80-95：
​```xml
……
​```

## 4. 约束 / 不能碰的
- 不能改 XXX（原因：……）
- 必须兼容 YYY
- 本项目铁律见 `collab/PROJECT-BRIEF.md` 第 4 节，相关的是第 X 条

## 5. 要什么产出（选一个，写死）
- [ ] 根因假设 + 每条假设的验证步骤
- [ ] 可直接替换的代码片段 + 落点（文件:行号）
- [ ] 两个/三个方案对比 + 影响面清单，让我拿给用户拍板
- [ ] review 结论，按「会崩 / 会静默失效 / 只是不好看」分级

## 6. 验收标准
（怎么算弄好了。要可验证，比如"构建 exit 0 且 XXX 功能实机点一遍正常"）
