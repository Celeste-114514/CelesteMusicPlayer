# 播放队列页面改造方案

日期：2026-10-28。依据用户提供的 ECHO 队列截图、本机 ECHO `src/renderer/pages/QueuePage.tsx` 及 Celeste 当前代码。这份文档是方案，本轮不实施队列整页改造。

## 目标与整体构图

队列页应回答三件事：**现在播什么、接下来播什么、怎样调整接下来的顺序。** 保留现有顶部分类导航、全局播放栏和 Windows/Apple 外观，不加入截图里的第二套侧栏或窗口外框。

```text
队列     来源说明                  共 N 首 · 剩余时长
┌───────────────────────────────────────────────────┐
│ 大封面  正在播放                         下一首封面 │
│         歌名、艺人、专辑                 歌名、艺人 │
│         音质、喜欢、更多操作             时长       │
│         本曲进度                                   │
└───────────────────────────────────────────────────┘
播放顺序模式                     衔接设置（已支持能力）
接下来播放     搜索队列   定位当前播放   选择   队列管理
握柄  序号/播放标记  封面  歌名/艺术家   音质  来源  时长  更多
 ⋮⋮       1          ▣   当前歌曲       …      …    …      …
 ⋮⋮       2          ▣   下一首         …      …    …      …
                        ……
```

推荐顶部播放卡片约 210–240px 高，封面 148–176px；普通列表行约 60px，封面 44–48px。920px 以下隐藏次要列、压缩下一首预览；720px 下当前/下一首上下排列，搜索与管理换行，保留握柄、歌名和时长。颜色跟随当前浅深色和预设，不把截图的黑底硬编码进所有外观。

## 页面各区的具体行为

| 区域 | 应有行为 | 需要避免的问题 |
|---|---|---|
| 顶部摘要 | 标题、队列总数、总时长/剩余时长；已知时显示来源 | 当前接口分批返回 200 首，不能把已加载部分的时长冒充整队列总时长 |
| 正在播放 | 大封面、标题、艺人/专辑、音质，喜欢/更多；封面可进详情 | 和全局底栏共享播放状态，不再自建一套播放会话 |
| 本曲进度 | 细进度条和时间，支持拖动定位 | 不把整曲波形再堆成第二个高大的底栏 |
| 下一首 | 显示引擎实际预定的下一条 | 随机模式没有确定预览时显示“下一首随机选择”；单曲循环明确当前曲目会继续循环，不按数组后一项胡猜 |
| 播放模式 | 沿用已有顺序、随机、列表循环、单曲循环、播完一次等语义 | 截图只有部分模式，不能因此丢掉 Celeste 现有能力 |
| 衔接方式 | 使用现有无缝预载/交叉淡化能力；显示实际可用条件 | 不凭截图增加尚未接入的“智能过渡”“本地智能电台”假开关 |
| 搜索 | 仅搜索这份队列，匹配歌名、艺人、专辑；清除后恢复同一位置 | 搜索不能改实际播放顺序，不触发播放全部或重建队列 |
| 定位当前 | 滚动到实际播放条目并轻高亮，用户离开后仍可回来 | 按条目身份定位，不能只按歌曲文件路径找第一条 |
| 单行操作 | 双击/Enter 播放；拖握柄排序；更多菜单复用收藏、加入列表、移除等能力 | “移出队列”与“从磁盘删除”必须明确分开，队列页不把删文件当主要操作 |
| 多选 | 选择后出现批量移出队列、加入播放列表、导出；取消选择不丢滚动 | 不把多选模式下的普通点击误认为播放命令 |
| 队列管理 | 保存为播放列表、导出、清除已播、清空等；危险性不同的操作分组 | 清空当前队列要说明当前歌曲如何处理，提供可恢复的队列快照 |

## 排序、拖动与当前播放的约定

1. 正常视图严格按真实队列顺序展示，不再默认套普通曲库的排序器。
2. 拖动只调整排队顺序，不重启当前曲目；即使队列中同一首歌出现两次，也保留正在播放的那次条目。
3. 当前已有原生队列 `move` 接口、revision 校验和播放序号保持逻辑，可直接复用。页面的插入线、边缘滚动、键盘 Alt+上下沿用弹出队列行为。
4. 有搜索过滤时首版禁用拖动并说明“清除搜索后调整顺序”，避免把不可见条目挪到用户预料之外的位置。
5. 如增加“按艺人/专辑/年份整理队列”，这是修改实际队列的明确操作：先显示新顺序预览，应用后可撤销。不能把普通列标题排序悄悄变成重排。
6. 自动切歌、添加、移除、拖动均使队列 revision 更新。过期操作拒绝并刷新，不能把旧序号应用到新队列。

## 数据与代码落点

| 位置 | 现状与建议 |
|---|---|
| `outputs/webview2-shell/browse.js` | 当前 queue 与多个分类共用列表渲染。新队列页拆成独立模块，避免改动喜欢、最近播放、文件夹等页面 |
| `index.html`、`shell.js` | 加独立 `#queue-page` 与导航映射，沿用现有壳和底栏 |
| 新 `queue-page.js` / `queue-page.css` | 管顶部当前/下一首卡片、搜索、多选、长列表和拖动；只消费共享播放状态和队列接口 |
| `transport-panels.js` | 保留快捷队列弹窗，和整页使用同一份队列数据及操作，不维护两个相互独立的队列 |
| `MainWindow.WebTransport.cs:WebQueue` | 现有 get/play/move 与 revision 可用。补 summary、当前条目、实际 next 预览、专辑/来源/音质字段；summary 在后端整份队列上计算 |
| `MainWindow.WebBrowseActions.cs` | 现有 `removeQueue` 等操作先复用；新增批量/管理操作时在宿主集中校验 |
| `WebQueueRules.cs` | 保留 CUE/重复条目和播放序号规则，扩充批量重排、删除的回归覆盖 |

队列来源目前没有完整的来源历史。第一版仅展示已知信息或“当前队列”，不能把歌手名推测成队列来源；后续可在“从专辑/列表播放”的入口记录清楚来源名称。

长队列采用行虚拟化或受控分段，初始只渲染可见区及少量缓冲。头像/封面异步加载，队列更新不要每 250ms 整表重建。进度在顶部卡片局部更新，当前播放标记按索引更新。

## 分阶段交付与验收

- **第一阶段**：独立队列页面、顶部摘要/当前/下一首、准确列表、搜索、定位、单行拖动。完成后即可替换现在的通用队列列表。
- **第二阶段**：多选、批量移除/加入列表、保存/导出、清除已播、撤销。
- **第三阶段**：已支持的衔接设置与预载状态说明；智能电台/智能过渡需要另立音频和推荐任务，不在 UI 改造里假装完成。

验收包含：101 首与数千首队列；CUE 同文件分轨；重复歌曲；播放中拖动；搜索后清除；随机/单曲循环；窗口缩放；Windows/Apple 深浅色；移除当前条目；操作与自动切歌同时发生。当前曲目不能错换，下一首必须符合引擎的实际顺序。
