# W13 播放域续：队列预览 + 音频链投影 — 2026-10-30

两提交：`f58581e`（队列预览）、`548aac5`（音频链）。

## 这一轮的验证方式变了

前几轮靠「编译 + 回归命令通」判断，这轮这两刀都是**纯函数搬移**，所以换了更硬的办法：

1. 用改动前的二进制采集一份真实回包（`tools/W13WireProbe.cjs`，走真进程 + CDP）；
2. 改代码、发布；
3. 用改动后的二进制采同一份回包；
4. **逐字段递归比对**。

比对范围：`queue`、`nowPlaying`、`home`、`folders`、`audioChain`、`audioReadout`、`appSettings` 七组。
两刀各自比对一次，**两次都是 0 处字段差异**（含嵌套数组、数值精度、字段顺序无关）。

## 第一刀：队列的上一首 / 下一首预览（`f58581e`）

`WebQueuePreview` 接管 `MainWindow.WebTransport` 里的两个私有方法，签名是纯的：
`(曲目数组, 当前下标, 顺序解析器) → 回包对象`。

这块的规矩（原样保留）：
- 上一首直接用播放器的 `ResolvePreviousIndex`，**网页不另算一遍**——卡片写哪首，点下去就得是那首。
- 下一首**不真摇随机数**：随机模式如实报 `random`，否则预览一摇就把真要播的那首摇走了。
- 单曲循环报 `self`，顺序播放到尾报 `none`。

## 第二刀：音频链路投影（`548aac5`）

`WebAudioChainService` 接管 `MainWindow.WebAudioChain.cs` 全部内容：
「音频链」面板的完整描述（节点、格式、诊断、DAC、电平、事件）+ 极客预设那排技术读数（OUT/FMT/FLAG/BUF）。

它只取一支委托：`() => AudioSignalPath.Capture(_audioEngine, DspRackGlobalBypassed)`。
**自己不做任何口径判断**——拿不到就是 null，前端显示「—」，绝不从源文件规格猜输出规格。

## 验证汇总

| 项 | 结果 |
|---|---|
| 全量 Rebuild（两刀各一次） | 0 个 `error CS`；警告 554 / 555 / 554（末尾回到基线） |
| 自包含 publish | 两次都成功（清理重试脚本，均第 1 次过） |
| 回包逐字段比对 | 两次均 **0 差异**（七组命令） |
| 标准回归（冷启动 + 重载） | PASS：13 条命令 ok、无 JS 异常、关闭 exit 0 |

## 没验到的

- 队列预览只在「队列 1 首、顺序=列表循环」这一种状态下比对过。随机/单曲循环/顺序到尾这几种分支
  靠「逻辑原样搬运」保证，没有逐个工况取证。
- 音频链快照依赖当前设备状态；比对是在同一台机器同一设备下做的，换了输出设备没有对照。
- 未播放音乐、未做干净机验收。

## 进度

`IWebPlayerServices` 47 条成员：**15 条已走独立服务**，32 条仍直连 MainWindow。

现在播放域剩下的硬骨头是**引擎与会话**：起播/停止、无缝接续、SMTC、播放历史写入、输出模式切换。
这些都要真的出声，不能像上面两刀那样用回包比对证明等价，需要你配合做一次实听验收。
