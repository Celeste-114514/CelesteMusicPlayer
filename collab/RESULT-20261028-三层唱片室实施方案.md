> 日期：2026-10-28（北京时间）
> 作者：Codex；接收者：WorkBuddy。
> 本文件是实施方案，不表示相关功能已经实现。本轮仅交付此文档，不修改播放器。
> 开工前必须读 `collab/PROJECT-BRIEF.md`，再查看当前 git status、近期 diff 和相关任务单；本文中的代码事实以撰写时核对结果为准，动工时须复核。
> 产品主界面是 WebView2 网页壳，源码在 `outputs/webview2-shell/`。不要在 dist 里开发。

## 0. 先把目标读准

最终做的是一个可以使用真实本地音乐库的三维唱片空间，分三层：

1. **第一层选专辑艺术家**：一个专辑艺术家一个抽屉；多个抽屉构成直立柜体。只看铭牌与唱片侧脊，不要求显示专辑封面。
2. **第二层选专辑**：选中的艺术家抽屉被抽出，里面整叠唱片连续展开，间距增大、轻微侧转，露出部分封面。浏览、单击、滚动、排序均有三维过渡。
3. **第三层播放**：确认播放某张专辑，唱片进入右侧虚拟 CD 机，有装载动画，然后由现有播放引擎开始播放。

三层是同一空间内的三个操作阶段。不要实现成三个风格断裂的普通网页，也不要把“第三层”理解为再弹一个系统窗口。

最重要的连续关系：**柜子里的那个艺术家抽屉，就是第二层展开的那叠专辑；第二层选中的那张，就是进入 CD 机播放的那张。** 数据身份与画面身份必须始终一致。

### 0.1 用户明确要求，不能擅自删减

- 入口放在主页。
- 场景占满应用页面，覆盖现有底部状态栏／播放栏。
- 按“专辑艺术家 → 专辑”组织。
- 第一层的专辑暂不需要封面。
- 选艺术家之后，整组专辑以动画进入第二层。
- 第二层从紧密的一叠唱片开始展开，增加间距并微微侧转，显示部分封面。
- 单击专辑和滚动时，保留当前莱茵模型那种精细、连贯的动作感。
- 第二层允许改变排序，重排本身也有动画。
- 右侧有虚拟 CD 机，播放前有入机动画。
- 最终模型精致程度以当前莱茵模型为基准；概念视频只是讨论材料。

### 0.2 本方案提出的默认设计，实施时按此落地

以下是 Codex 对尚未明确细节的具体建议，不应写成“用户已逐项确认”：

- 第一层用“直立柜体 + 横向艺术家抽屉”，不沿用当前平铺无限阵列。
- 单击抽屉铭牌即进入该艺术家；悬停只预览，不自动进入。
- 第二层单击专辑只选中；再次单击同张仍不播放。播放用清楚的“放入 CD 机”按钮，或选中项的 Enter。
- 第二层滚轮一次推进一个目标专辑；快速连续滚动合并目标，平滑追随。
- 第二层默认按发行年份升序排列，缺年份的靠后；同年按专辑名称、最后按稳定 ID 打破平局。
- 入机采取“唱片盒停靠在机器旁，圆形光盘从盒中进入机芯”的物理表达，避免整只方盒穿过圆形机芯。
- 从第三层返回第二层时继续播放；返回是浏览行为，停止播放必须有明确操作。
- 应用系统标题栏可保留，用来拖动窗口、最小化、最大化和关闭；“占满页面”指标题栏以下整个客户内容区，不强制进入系统独占全屏。

若用户后续调整以上细节，按用户最新指示更新方案，不能把本文件当成高于用户的规则。

### 1.2 已知接口，以现有源码为准

```js
CelesteShell.getLibrary()             // 当前来源范围的歌曲
CelesteShell.getAlbums()              // 当前来源范围可见的专辑摘要
CelesteAlbums.getAlbums()             // 专辑模块已构建的专辑
CelesteShell.getState()               // 当前播放状态快照
CelesteShell.playTracks(trackIds)     // 按指定 ID 列表请求播放
CelesteShell.playTrack(trackId)       // 请求播放一首
```

生产桥发送的数据是 `{kind:'celeste.command', version:1, command:'playAll', trackIds:[...]}`，字段叫 **command**，不是 action。不要因示例代码误写字段。

`send()` 会先把目标曲目写到前端状态，且 `playing:false`，用于显示“正在准备播放”。这不是音频已经成功开始的证明。必须继续等待宿主确认的状态或错误消息。

当前事件：`celeste:library`、`celeste:state`、`celeste:message`、`celeste:navigate`。具体字段与消息先后顺序，实施前从当前源码确认。

## 2. 全局页面布局

### 2.1 入口

在主页可见的主要区域增加“唱片室”入口，副文案可为“按艺术家翻阅你的专辑”。入口是用户能发现的卡片或按钮，不藏进更多菜单。

- 点击后不先跳专辑网格，不依赖专辑页正在显示。
- 直接从当前真实音乐库构建第一层。
- 成功后移除旧专辑页“莱茵阵列”独立入口，避免两套不一致的访问方式。
- 未加载完音乐库时显示进度／准备状态；空音乐库仍能进入空场景，提供调用既有添加音乐入口的按钮。
- 加载失败提供重试和返回主页；不能留下无法退出的空白 WebGL 画布。

### 2.2 整个客户区的占用

场景进入后覆盖导航内容、底部播放栏、原 toast 之外可能浮出的菜单。原底部条不能露出一条边，也不能透过玻璃看到。

- 测量实际标题栏边界，场景从标题栏下方到客户区最底边；不要复制旧 `bottom:100px`。
- 底部条及其可点元素进入不可交互状态；退出后恢复原状态与焦点。
- 只提高 z-index 不够：防止键盘 Tab、快捷键、滚轮透传到背后页面。
- 进入前收起旧弹窗／菜单；退出时不重开旧菜单。
- 全场景使用自己的返回、播放状态与错误提示，不能依赖被覆盖的播放条。
- 全页面 DOM 控件使用现有 SVG 图标体系；不把 Unicode 字符当图标。

### 2.3 三层布局约定

第一层柜体为主，第二、第三层左侧唱片区域约 62%，右侧 CD 机约 38%。这是起始比例，按实机阅读与模型遮挡调整。

- 顶部：左侧层级返回与当前艺术家；右侧退出唱片室、必要的画质设置。
- 第一层：柜体居中；索引／搜索靠边；CD 机可在右边背景低调停放，不能抢艺术家选择。
- 第二层：左侧艺术家唱片展开；右侧 CD 机清楚可见。排序控件固定在唱片区上方。
- 第三层：镜头靠近 CD 机，仍保留艺术家、专辑与返回入口。
- 文案只承担当前需要的引导，例如“选择艺术家”“选择专辑”“放入 CD 机”。不要把调试参数、阶段名称、模型信息堆进产品 UI。
- 不允许右侧整个信息区与内部曲目列表同时出现双滚动条。曲目列表保留一个明确的滚动容器。

## 3. 第一层：艺术家抽屉柜

### 3.1 外形和空间关系

第一层必须读作“直立柜子”。柜体有侧壁、横梁、导轨、底座，抽屉在结构内有固定位置。不能是几块卡片漂浮在空中。

每位专辑艺术家对应一个宽而较薄的抽屉。抽屉前面有铭牌，内部是紧密排列的该艺术家的专辑。用户透过透明材质能看到盒子层次与侧脊，不在此层展示封面墙。

建议从一个柜体入手：可见 5 个完整抽屉及上下各一点边缘，窗口足够高时可以显示 7 个。中央是当前聚焦艺术家，前后相邻艺术家仍能辨认。

铭牌至少显示：

- 艺术家名称，视觉优先级最高；长名字采用可读的换行或省略+完整提示。
- `N 张专辑`，数字来自真实归组。
- 稳定的视觉编号，仅作装饰，不能充当歌曲／专辑业务 ID。

抽屉厚度不要直接等比于专辑数量，否则只有 1 张专辑和 100 张专辑的艺术家会破坏布局。柜面高度统一，数量由铭牌和内部可见侧脊表达；内部模型可抽样绘制，所有真实专辑仍必须能在第二层找到。

### 3.2 材质标准

- 柜体：偏暖的浅色金属／陶瓷底材，边缘真实倒角。
- 抽屉：透明或轻磨砂玻璃，边框、连接点与导轨可见。
- 细节：小螺丝、刻线、细窄暖色指示光，克制使用。
- 遮挡：盒子与抽屉接触处有接触阴影；不能像无重量的半透明贴片。
- 铭牌始终可读；背景太亮时调整局部材质／光照，不靠整张黑底大标签覆盖模型。

禁止用概念视频那张生成图片充当可交互柜体。它只能作为材质和构图参考，不能替代真实几何、真实拾取与真实专辑数据。

### 3.3 第一层动作

| 输入 | 结果 | 禁止结果 |
| --- | --- | --- |
| 悬停某个铭牌／抽屉 | 该抽屉前探约自身深度的 3%～5%，边缘指示光轻亮 | 自动切层、自动播放 |
| 单击抽屉 | 锁定 artistId，启动第一层到第二层动画 | 随机抽另一名艺术家 |
| 滚轮／上下键 | 艺术家列表沿柜体导轨平滑移动，聚焦项变化 | 整个柜体呼吸、各抽屉无规则起伏 |
| 搜索艺术家 | 过滤第一层候选并平滑定位；显示结果数 | 搜索歌曲标题后偷偷换分组 |
| 字母／拼音索引 | 跳到该首字母附近第一位艺术家并显示名字 | 必须靠鼠标滚数百次才能找到人 |
| Esc／退出 | 回主页，恢复此前滚动和焦点 | 顺手停止当前音乐 |

静止时柜体与抽屉稳定。不要把现有莱茵大范围呼吸波纹直接套到第一层柜体。

### 3.4 大音乐库与边界

- 按专辑艺术家名称稳定排序，数字自然排序；中文按既有中文排序规则处理。
- 只渲染可见抽屉及少量上下缓冲，不能为几千名艺术家创建几千套完整高模。
- 第一位和最后一位有明确边界，不无限循环制造重复柜子。
- 只有 1 名艺术家时仍画出有完整结构的柜体，不塞四个重复的该艺术家凑数。
- 返回第一层保持 artistId、滚动位置、查询和索引位置。

## 4. 第一层 → 第二层：整组抽出再展开

### 4.1 动画分段，初始建议总时长 1.0～1.4 秒

| 相对时间 | 物体动作 | 相机与 UI |
| --- | --- | --- |
| 0～180 ms | 当前抽屉锁定，其他抽屉轻微减弱 | 保留原艺术家名字，禁止重复进入 |
| 120～500 ms | 当前抽屉沿导轨抽出，里面唱片保持紧密叠放 | 相机平滑靠近抽屉 |
| 400～850 ms | 抽屉及整叠唱片移向第二层工作区域 | 柜体退向背景或淡出；CD 机进入清楚构图 |
| 650～1250 ms | 专辑间距逐步拉大，角度逐步侧转 | 艺术家标题、排序与选择提示出现 |

时间段重叠是为了连续，不要分四次停顿，也不要切黑屏再加载另一套场景。

### 4.2 连续性要求

- 能看出唱片从刚才那个抽屉里出来，而非在新位置凭空复制。
- 同一 albumId 在两层之间映射到同一个逻辑实体；模型为性能切换实例也必须视觉连续。
- 若改变父节点，先把旧 world matrix 转换到新父节点局部坐标，再开始补间，不能 position 直接归零。
- 专辑封面在进入第二层前请求；已有缓存的封面在首个可展示画面即出现。
- 不等待全部艺术家、全部封面加载才允许进入。当前可见项缺图使用同尺寸默认封面，稍后单项交叉淡入。
- 抽屉外框可退到侧边／后方作为来源提示，不能遮住第二层唱片。
- 返回第一层采用反向动作：唱片收紧 → 入抽屉 → 抽屉入柜；恢复原位置。

## 5. 第二层：专辑从紧叠到可翻阅

### 5.1 静态几何与镜头

不要直接改成封面正对镜头的普通二维卡片网格。基础形态仍是一叠／一列有厚度的实体唱片盒。

统一定义唱片局部坐标：Y 为竖直，唱片面法线为局部 +Z，盒脊沿局部 Y。布局函数输出每张盒子的世界位置和旋转。后续动画不能各写一套不一致的坐标假设。

第二层稳定状态建议：

- 一次完整看到约 5～7 张，超出部分可露边，随窗口宽度调整。
- 非选中项相对镜头侧转，先以“封面法线与镜头方向夹角约 55°～65°”试做；用户能看到约三分之一到一半封面。
- 选中项向前抬出／抽出，旋转到约 10°～20°，让完整封面可辨认。
- 相邻盒子保持层次，不互相穿插；投影后有足够可点区域，不能看得到却永远点不中。
- 每张封面处于盒子本体上；不要仍然只在右侧放一张小封面。
- 选中项显示专辑名称、年份、曲数。不要让用户只能靠一小块色彩猜是哪张。

角度只是灰模起始参数，不是精度验收指标。验收看实际封面辨识、空间层次与可操作性。

### 5.2 封面与莱茵模型结合

- 保留外壳厚度、倒角、螺丝、磨砂玻璃和机械细节。
- 把封面装在盒内的独立平面／薄片网格上，合理排列深度，避免共面闪烁。
- 将原双环内构改成适合唱片的衬纸／CD 区域，至少不能让双环完全挡住封面。
- 默认立即能辨认封面，不沿用“抽出后再等数秒解密才能看见”的动作。
- 可留 100～180 ms 的细微材质提亮，不能把它做成阻塞性的解密流程。
- 封面保持原比例，不拉伸；方形封面正常铺满，异形封面按统一背景容纳。
- 颜色按 sRGB 处理；核对浏览器图片与模型封面是否有明显色差。
- 图片失败显示统一衬纸+专辑名；重试失败不阻塞选择和播放。

### 5.3 选择行为

| 输入 | 结果 |
| --- | --- |
| 单击任意可见专辑 | selectedAlbumId 改为该项，它前探并展示更多封面，原选中项归位 |
| 再单击当前专辑 | 保持选中，不开始播放 |
| 滚轮／左右键 | 前后推进选中专辑，布局沿轨道移动；选中项始终进入可辨认位置 |
| 快速连续滚动 | 合并到最新目标，从当前显示姿态继续运动，不能积压几十段动画 |
| 点击“放入 CD 机”／当前项 Enter | 启动装载到第三层 |
| 返回艺术家／Esc | 收拢当前叠片，回第一层 |

莱茵现有选择波纹可用于第二层的邻近唱片响应，但幅度必须小，作用范围有限。不能让整列上下漂浮，导致用户没法稳定点选。

选中与播放必须是两个状态：用户浏览其他专辑时，CD 机仍可播放原来那张，不能看到 selectedAlbumId 变化就立即换音频。

### 5.4 排序与排序动画

提供：发行年份、专辑名称、添加顺序（仅后端有可靠值时），以及升／降序。不要用当前数组下标伪造“添加时间”。初版不必放随机排序。

排序操作步骤：

1. 保存每个 albumId 的当前显示 transform，包括动画进行中的实际姿态。
2. 计算新的 ID 顺序；始终保留 selectedAlbumId。
3. 根据 ID 计算新目标位置；选中专辑仍在可阅读的中心区域。
4. 唱片轻微收紧／分层让路，随后沿错开的深度路径移位，最后展开落位。
5. 用约 450～750 ms 完成一轮；少量错峰即可，不能每张串行播放导致几十秒等待。
6. 频繁改排序时覆盖目标，从当前位置重算；不能销毁全部 mesh 再重建后淡入。

**排序只改变浏览顺序，不改 album.trackIds 的真实碟号／曲号顺序。** 不改变持久化音乐标签，也不偷偷改变当前播放队列。

### 5.5 专辑数量边界

- 1 张：简短抽出动作后直接作为选中项，不虚构其他专辑。
- 2～4 张：居中展开，不强制填满七个槽位。
- 大量专辑：按 ID 做可见窗口与缓冲，滚动后所有专辑可达；不能截断到前 32 张。
- 无封面、同名不同版本、多碟：保持独立 albumId；多碟在详情中显示 Disc 分组，首版仍以一个专辑盒表达，不凭空拆成多张专辑。

## 6. 第三层：CD 机与真实播放

### 6.1 CD 机模型要求

右侧 CD 机必须是独立三维物体：机壳、脚垫、真实厚度的透明盖板、圆形机芯、轴心、装载路径、必要的按钮／状态灯。

建议采用前方可视的玻璃盖机型，使用户能看见盘面与旋转。不要直接用一张机器图片或一个圆圈配播放图标冒充精细模型。

CD 机与盒子的材质、光源方向、阴影强度一致。原莱茵外壳是精度标杆；概念视频中的机器只作为外观方向，尺寸和机械运动需要重新设计。

### 6.2 第一次播放的时序

建议装载总长约 1.2～1.8 秒，实际播放准备可以更长，但必须清楚反馈：

| 时段 | 画面 | 业务行为 |
| --- | --- | --- |
| 点击当帧 | 锁定目标，显示选中的专辑名 | 拍下 albumId、trackIds、音乐库 revision，创建唯一装载 token |
| 0～450 ms | 选中盒子离开叠片，移动到机器旁 | 尚不发送 playAll，原音乐可继续 |
| 350～950 ms | 盒子打开／显露光盘，盘片沿装载路径进入机芯 | 仅准备视觉；不启动第二套音频 |
| 900～1500 ms | 盘片落到轴心，盖板闭合，进入待播姿态 | 在定义好的装载提交点，发送一次 playTracks(snapshot.trackIds) |
| 收到宿主 playing=true 且 trackId 属于目标专辑 | 盘片加速旋转、播放指示灯亮 | 标记真实播放中，同步实际曲目、时长与进度 |
| 宿主仍在准备／失败 | 显示“正在准备播放”／具体错误 | 不能用固定延时把 UI 强制改成 playing=true |

提交点可以在闭盖完成时；必须在代码和测试中只有一个明确位置，不能在 click、动画 onComplete、状态回调分别调用一次播放。

### 6.3 切换、暂停、失败与返回

- 播放同一张、已经装载的专辑：用户按继续播放只调用既有继续命令，不重新跑装载。明确“从头播放”才重建队列。
- 播放另一张：旧盘减速→退到原盒／停放位→新盘装入。旧盘身份由 loadedAlbumId 管理，不能退回当前正在浏览的另一名艺术家抽屉。
- 原音乐在新播放命令提交前继续；提交后的切换、停止旧音频由现有引擎负责，不在前端发多余 stop 破坏播放历史。
- 暂停：盘片减速停住，保留装载状态；继续播放再加速。
- 换同一专辑内的曲目：保持装载盘，不每首退盘重装。
- 快进／拖进度条：调用已有 seek 能力，以实际宿主状态回显；不伪造时长。
- 错误：停止假旋转，显示重试和返回；重试是一次明确的新请求，不能无限自动重试。
- 装载提交前返回／退出：取消当前 token，不发播放请求，把物体回到稳定位置。
- 提交后返回：不当成“取消已经发生的播放”。回第二层继续听，保留机器上的 loadedAlbumId。
- 第三层 Esc：先关闭菜单／对话框，否则回第二层；第二层再按 Esc 回第一层；第一层再按 Esc 退出。
- 应用外部控制／系统媒体键／队列切歌：以真实 trackId 更新机器。未知于当前库的曲目显示“外部播放／当前曲目”，不能冒充选中的专辑。
- 只浏览不播放、调整排序、返回第一层，都不发送音频命令。

### 6.4 第三层必备操作

原底部播放条已被覆盖，因此场景内至少有播放／暂停、上一首／下一首、真实进度、音量，以及返回浏览和退出。复用现有桥与快捷键规则，不建一个失联的装饰播放器。

重复键盘快捷键监听要处理：同一次按空格不能让旧播放条与新 CD 机分别切换一次，最终看起来没反应。

## 7. 数据模型：身份绝不能跟槽位走

### 7.1 第一层按谁归柜

使用**专辑艺术家 AlbumArtist**，不是每首歌的 Artist。推荐归组顺序：

1. 后端专辑摘要已有明确的 albumArtist：优先使用。
2. 已核对当前 WebTransport 的 album.artist 实际来自专辑艺术家分组时，可复用该语义并在适配器清楚命名。
3. AlbumArtist 为空白才回退 Artist；两者都为空白用“未知专辑艺术家”。

当前后端分组有 `item.AlbumArtist ?? item.Artist ?? ""`，**?? 不会处理空字符串**。实施时核查实际空值，不能认为已经覆盖了空白标签。需要修复时先检查是否影响普通专辑页、合辑与来源分组；不要仅在场景里另造一套与后端冲突的 albumId。

合辑的各首歌可能由不同歌手演唱，若其 AlbumArtist 是 Various Artists，就放在同一个该名称柜子，不按歌曲歌手拆散。多艺术家字符串先作为一个现有标签处理，不擅自按逗号／斜线拆分。

### 7.2 建议概念模型

```ts
type ArtistDrawer = {
  artistId: string;       // 稳定规范化键或宿主 ID，不能用排序下标
  displayName: string;
  albumIds: string[];
};
type RoomAlbum = {
  albumId: string;        // 沿用宿主专辑 ID
  artistId: string;
  title: string;
  year: number | null;
  coverUrl: string | null;
  trackIds: string[];     // 宿主的碟号、曲号顺序；不要按当前展示序重排
};
type RoomSession = {
  level: 'artists' | 'albums' | 'player';
  artistId: string | null;
  selectedAlbumId: string | null;
  loadedAlbumId: string | null;
  sort: { key: string; ascending: boolean };
  libraryRevision: string | number;
  transitionToken: number;
};
```

artistId 的规范化规则与曲库一致；如果当前只有名字，至少做 trim、现有不区分大小写规则，保留 displayName 原文。不能把“名称相同”直接等同于专辑相同。

### 7.3 来源过滤和重复数据

- 沿用用户当前选择的来源范围。
- 同名艺术家跨来源可以显示在同一抽屉里，但专辑保留宿主的 source-aware ID，不按专辑标题合并。
- 检查当前 `getAlbums()` 是“专辑含任意匹配曲目即保留整张”，还是 trackIds 也已过滤。播放集合必须符合既有来源规则，不能只看一首可见就把其他被排除来源的歌也带进来。
- 一张同名专辑的不同版本不能仅按 title 去重。
- 轨道／槽位／实例下标只是呈现位置。Raycaster 命中后用实例映射表找到 albumId，再查实体；不可用取模反推出身份。
- 当前 `%5` 视觉分列、空列重复填充、固定 32 行及旧循环导航必须从业务路径移除。新第一层有艺术家边界，第二层只包含该艺术家的专辑。

## 8. 状态机、打断与资源生命周期

### 8.1 建议状态及允许操作

| 状态 | 可做 | 暂时合并／禁用 |
| --- | --- | --- |
| loading | 返回、重试 | 拾取、播放 |
| artistBrowse | 搜索、滚动、选抽屉、退出 | 专辑播放 |
| openingDrawer | 返回取消、窗口调整 | 重复进入请求 |
| albumBrowse | 滚动、选专辑、排序、装载、返回 | 无 |
| rearranging | 返回、更新最新排序／选中目标 | 以旧布局再次创建独立时间轴 |
| loadingDisc | 提交前取消、退出 | 重复装载和重复发音频命令 |
| awaitingPlayback | 返回浏览、取消未来视觉操作 | 假设声音已播放、自动重复请求 |
| playerReady/playing/paused | 既有播放控制、返回浏览 | 重复加载同一已装载专辑 |
| error | 重试、返回、退出 | 无提示继续假播放 |

视觉状态和音频状态正交管理。场景位于 albumBrowse 时，音频仍可以是 playing。

### 8.2 中断规则

- 每次进入／退出场景、换艺术家、换装载目标更新 token；所有异步模型、封面、播放回调检查 token 与 ID。
- 新目标从当前显示 transform 开始运动，不回到上段动画起点。
- 窗口 resize 重算目标构图，保留当前艺术家和专辑，不回主页重建所有数据。
- 音乐库更新：优先按稳定 ID 恢复；仍存在的艺术家／专辑保持，删除的目标退回最近合法层级并显示简洁提示；不依赖上一版“一更新就强制关闭”。
- 最小化／后台：暂停 WebGL render loop，音频继续；恢复时与宿主同步，不能用后台经过的巨大 dt 一帧跳完错误动画。
- 用户退出：释放 RAF、事件、ResizeObserver、纹理引用、几何／材质、renderer；晚到的 load 也要释放。
- 缓存资源要有清楚的所有权；共享封面纹理不能在一个实例销毁时把别处仍在用的纹理 dispose 掉。

## 9. 动画、性能与可访问性底线

- 动画使用真实 dt 和统一时间轴，不按帧号累加位移；30/60 FPS 下总时间基本一致。
- 不叠加数套彼此争抢相机的动画。一个场景协调器拥有相机最终姿态。
- 减少动态模糊，不以“看不清封面”掩盖模型或性能问题。
- 高／性能两档：降低阴影、AO、像素比、玻璃采样，保留倒角轮廓、必要结构、封面与选择反馈。
- 默认先用现有机器实测决定；参考目标 1920×1080/DPR 1 稳定接近 60 FPS，性能档至少稳定 30 FPS。记录实际窗口、GPU、画质与帧时间，不能把其他机器的上游跑分作为本机结论。
- 首次模型加载与封面加载单独计时；不能为隐藏的全部库预生成几千张大封面纹理。
- 音频正在播放时测拖动、排序和入机，不能引入可听的卡顿。
- 第一层与第二层有与当前可见项对应的可访问 DOM 控件／列表，不要求盲人操作 WebGL 坐标。
- Tab 不穿透背景；焦点可见；Esc 分层返回；Enter 按层级语义工作。
- 系统“减少动态效果”开启时，把大幅抽取／相机运动改为快速定位或短淡入；仍保留完整语义与播放确认顺序。

## 10. 分步实施：不要一口气把所有东西混在一起

每阶段先实现可验证闭环，再推进下一阶段。每阶段记录实际文件和验证结果；是否拆多个可回退 commit，按仓库“一次任务一个 commit”的约定，把阶段定义成独立子任务，不能一边交付半成品一边混入别人改动。

### 阶段 A：清点、备份、数据准备

操作：

1. 查看当前 git status、近期 diff；本方案撰写时 WebSettings、WebShellWindow、settings.js/css 等存在其他改动，不覆盖它们。
2. 保存本次相关源文件与当前 dist 的可恢复备份；记录源提交与现有启动路径。
3. 核对曲库 DTO 的 AlbumArtist、专辑 ID、来源范围、年份、封面 URL、trackIds。
4. 编写独立 room-library 适配层，用真实样本输出艺术家→专辑清单，暂不改渲染。
5. 先处理空 AlbumArtist、同名版本、合辑与多碟的身份规则。

产物：数据契约、样本映射、备份位置与文件清单。

验收：人工抽查至少 3 名艺术家；其中有一张合辑、一张多碟或同名版本。柜子计数与现有库一致，trackIds 可回查到正确歌曲，重新排序不改 ID。

### 阶段 B：全页面外壳和主页入口

操作：主页加入口；实现独立场景状态和退出；覆盖底部条并阻止背后焦点／输入；先用灰模。补场景内基本播放控制。

产物：可进入、退出、正确覆盖页面的场景，不需要此时就完成精细模型。

验收：普通窗／最大化／矮窗都没有底部漏边；Tab 不进背景；退出恢复主页；播放中进出不打断声音。空库和 WebGL 失败能退出。

### 阶段 C：第一层柜体与艺术家操作

操作：灰模完成柜体、可见抽屉池、铭牌、滚动、搜索、索引、ID 拾取。确认空间比例后替换为精细柜体材质和结构。

产物：真实艺术家的柜子；截图至少包含正面、稍侧视角、长名字、单艺术家和大库定位。

验收：可明确看出柜体；一艺术家一抽屉；没有封面墙和整柜呼吸；滚动不重复假艺术家；1000 个艺术家也只生成有限可见实例。

### 阶段 D：抽屉到第二层的连续过渡

操作：实现整叠专辑随抽屉移出、相机跟随、换父节点 world transform 保持、展开与返回。封面开始加载并贴到盒子本体。

产物：同一名艺术家进入、展开、返回的录屏；包括 1 张、3 张、很多张专辑。

验收：可追踪同一批实体；没有凭空换场、错艺术家、等待几秒解密才看到已有封面；缺图不阻塞。

### 阶段 E：第二层选择、滚动、排序

操作：实现选中突出、前后归位、滚动目标合并、排序动画、可见窗口、名称提示与单滚动曲目区。

产物：一段包含单击、快速滚动、两次连续排序和返回的实际录屏；测试 ID 映射。

验收：点击哪张就选哪张；排序后同一 albumId 仍选中；所有专辑可达；动画没有穿模；此阶段浏览绝不调用播放桥。

### 阶段 F：CD 机模型和装载动作

操作：先用灰模验证尺寸、盒子停靠点、盘片路径、盖板和轴心；再细化到莱茵模型精度。实现 loadedAlbumId 与装载 token；此阶段可用显式测试适配器验证视觉，交付前必须切回真实宿主。

产物：从选中专辑到盘片装入，以及换盘／退盘／暂停姿态的视频；机器多角度截图。

验收：没有整个方盒穿进圆形机芯；装载前后是同一专辑；快速点击不生成多张漂浮盘；旧盘回到正确来源／停放位。

### 阶段 G：真实播放闭环与异常

操作：在唯一提交点调用既有 playTracks；监听真实状态驱动旋转；接场景内控制、错误、外部切歌、后台恢复。

产物：带真实声音的实机验证记录，桥命令 ID 和实际播放 ID 的对应证据；不要在证据中输出私密路径。

验收：动画完成后确实开始所选专辑；playAll 每次确认只发一次；播放失败没有假播放；换曲不重装同一张盘；退出仍可继续听。

### 阶段 H：打磨、发布与回退交接

操作：检查响应式、触控板、键盘、画质、减少动态效果、资源释放；构建、同步当前 dist、核对 hash；补 VERIFY 文档与启动说明。

产物：可运行版本、三层连续录屏、实测性能、已知限制、回退步骤、独立提交。

验收：按下一节完整执行，不用“构建通过”替代实际效果验收。

## 11. WorkBuddy 必须执行的验收清单

### 11.1 功能数据

- [ ] 从主页进入；进入不依赖先访问专辑页。
- [ ] 中文／英文／数字名字排序稳定；空白专辑艺术家有清楚归属。
- [ ] 合辑不按各首歌演唱者拆柜；多碟不丢曲；同名专辑不误合并。
- [ ] 来源过滤下显示和播放范围一致。

## 13. 为避免理解跑偏，交付前再读一次

1. 第一层是**艺术家抽屉柜**，抽屉里是专辑侧脊；不是所有专辑平铺的旧无限阵列。
2. 第二层是**同一抽屉的专辑展开**，不是另开一个普通封面网格页。
3. 专辑封面属于**盒子模型本体**，右侧小图不能算完成这个要求。
4. 第二层的选择、滚动、排序与播放动作分开，不能随便看一张就切歌。
5. 第三层是**CD 机装载与播放状态**，真实声音由既有 Celeste 引擎负责。
6. 柜体稳定；莱茵的波纹、轻抬、抽取手感主要用在第二层与过渡，不把整个柜子做成呼吸的浮动阵列。
7. 全页面场景自带必要控制，覆盖底部条后不能让用户失去暂停／退出入口。
8. 概念视频是讨论方向，实际交付必须是真模型、真数据、真拾取、真播放。

WorkBuddy 的最终汇报应包括：完成了哪几个阶段、对应提交、实际运行路径、用户如何进入、三层实际录屏、构建与实机验证结果、未完成细节和可执行回退方法。不要把“已接上接口”描述为整个体验已经完成。
