# Windows / Apple 预设细化方案

日期：2026-10-27。此文件是下一轮外观实施方案；本轮已落地的是 Twilight 详情主题、轮盘定位、全屏和队列排序，未把下表的整套材质改造标成已完成。

## 现在为什么只有“有点像”

`WebAppearance.cs` 的 `windows-fluent` / `apple-silver` 当前主要区别是基色、圆角、间距、字体、底栏透明度与模糊。主工作区仍是实心大面板；背景层即使有图，内容层也会把它挡住。只把 blur 数值加大，毛玻璃仍然看不出来。

要改的是五个层次：窗口背板、页面内容、浮动控件、选中状态、交互反馈。先建立材质层级，再调颜色。Windows 和 Apple 各自具有浅/深配色，详情主题独立于外壳预设。

## Windows：Fluent · 云母与亚克力

主窗口以 Mica 的安静质感为基底，侧面抽屉、队列和菜单使用更明显的 Acrylic。Mica 会融合壁纸色调，它本身并不是透视窗口下方内容的透明玻璃；需要透视背景时应选 Desktop Acrylic。[微软材质概览](https://learn.microsoft.com/en-us/windows/apps/develop/ui/materials)、[Mica 与 Desktop Acrylic 的区别](https://github.com/microsoft/microsoft-ui-xaml/blob/main/docs/design-notes/mica-desktop-acrylic.md)。

以下数值是 Celeste 的建议起点，属于设计方案，不是微软的强制参数。

| 位置 | 外观与细节 | 建议起始值 |
|---|---|---|
| 整窗背板 | 默认低饱和冷灰云母感；用户可切“桌面毛玻璃” | 浅色基底 `#f3f3f3`；深色 `#202020`；窗口四周保留 1px 明暗边缘 |
| 真实桌面毛玻璃 | 在 WinUI 宿主使用 `DesktopAcrylicBackdrop`；WebView2 默认底色与网页壳共同透明，让系统背板露出来 | 原生宿主决定底材，网页不能再铺一层不透明 body；无特效时回退实色 |
| 应用内侧栏/抽屉 | 模糊的是应用内部封面/背景；加入稳定底色遮罩，保证文字对比 | blur 24–32px，饱和度 110–125%，浅色白遮罩约 78%，深色黑遮罩约 72% |
| 主内容 | 保持清楚，歌曲列表不用整块重模糊 | 阅读面 92–98% 不透明；用细线分组，卡片只轻微浮起 |
| 菜单/播放队列 | 薄玻璃面、细高光边、紧凑但不拥挤 | 圆角 8px；外阴影 `0 8px 28px #0002`；内描边 1px 白色 25% |
| 封面 | 比 Apple 更利落，保持真实比例 | 圆角 4–6px；窄阴影；不加厚重光晕 |
| 选中/当前播放 | 轻背景 + 细色条，不整行刷成高饱和蓝 | 浅色强调 `#0067c0`；深色更亮；当前播放保留独立图标/文字标记 |
| 控件 | 标准矩形带小圆角；主按钮明确，其余弱化 | 常规 32–36px 高、触摸模式 40px；焦点外框 2px |
| 按压/悬停 | 悬停提亮一层，按下收紧；松手快速恢复 | 悬停约 100ms，按压约 70ms，抽屉 180–220ms；不用明显弹跳 |
| 滚动与导航 | 保持内容位置稳定；导航展开轻淡变 | 轮盘位置相对外壳；边缘留白稳定，不随标题栏高度变化 |

**关键验收**：毛玻璃下面必须有实际内容或系统背板。把不同颜色的窗口放在 Celeste 背后时，只有“桌面毛玻璃”档应该明显响应；应用内 blur 只响应 Celeste 自己的背景。失焦、节能、高对比或减少透明度时保持清楚且能操作。

## Apple：Silver · 内容优先，控件悬浮

建议以银白与磨砂面为默认；另提供“Glass 控件”变体。Apple 对 Liquid Glass 的定位是导航和控件层，内容层仍需稳定可读；减少透明度、提高对比度时也要调整材质。[Apple Materials 指南](https://developer.apple.com/design/human-interface-guidelines/materials)。Celeste 在 Windows/WebView2 上提供这种视觉语言的实现，不声称使用 macOS 原生材质。

| 位置 | 外观与细节 | 建议起始值 |
|---|---|---|
| 背景 | 银白底、封面轻取色；内容区安静 | 浅色 `#f5f5f7`；深色 `#1c1c1e`；封面颜色只进入背景的低饱和区域 |
| 内容布局 | 大封面、明显的歌名字阶、更多留白 | 歌名 32–40px；艺人/专辑 17–19px；正文 14–15px；行高约 1.5 |
| 控件浮岛 | 播放控制/主题按钮成组悬浮，内容不逐张玻璃化 | 磨砂 blur 28–40px；浅色白底约 70%；深色灰底约 66%；细白高光边 |
| Glass 变体 | 只为浮岛/导航做双层高光与柔和边缘折射感 | 常规透明度比极透明效果更高；不让歌词和长列表透字重叠 |
| 播放键 | 圆形，体积感轻，按压自然 | 56–64px；按下缩至约 .96；180–240ms 温和回弹 |
| 菜单/队列 | 圆角更大，层次更柔和 | 圆角 16–20px；双层柔影；队列行 48–56px，行内保持清楚对齐 |
| 封面 | 作为主视觉，不给图片覆盖一层玻璃 | 圆角 12–16px；宽而浅的投影；共享封面进出动画 260–320ms |
| 字体 | 使用 Windows 上实际存在的字体栈；不随包分发 Apple 字体 | 英文系统 sans + 中文系统字体；字号/字重/行距共同调，不只换字体名 |
| 选中 | 浅蓝灰底与蓝色强调，暗色提高局部对比 | 蓝 `#007aff` 起步；当前歌词高对比，其它句降低权重但可读 |
| 动效 | 主要组件连续过渡，装饰安静 | 封面/控件进出可接续；长歌词与频谱不逐行叠加动画 |

**关键验收**：不开模糊时仍然能辨认层级；打开模糊后读歌词不费力。Glass 是控件层的质感，不能把整个页面变成看不清的透明板。

## 外壳预设与详情主题的组合

- Windows / Apple 只决定整个应用的公共材质和控件，Twilight 决定详情页构图。切换外壳时，不覆盖用户选中的详情主题。
- 内置详情主题首批保留“封面与歌词”“Twilight 音频仪表”。未来可增加“封面与歌词 + ECHO 式低强度音乐光晕”，作为可关闭选项。
- Twilight 主题沿用截图的网格、圆环、红色细线、右侧音频图表；深色变体保留同一几何结构。实际播放、歌词、队列、全屏共享同一个宿主。

## 实施落点与顺序

1. `WebAppearance.cs` 增加成组的材质参数：材质模式、染色、表面不透明度、模糊、边缘高光、阴影强度、减少透明度。State/Clone/Normalize/Schema 同步；不能仅往 CSS 加常量。
2. `WebShellWindow.cs` 根据材质模式调整宿主 SystemBackdrop 和 WebView2 背景，关闭/还原时恢复原状态。先验证当前 Windows App SDK 与未打包发布实际可用的 API；不为单个材质贸然升级整套 SDK。
3. `theme.js` / `theme.css` 统一消费材质令牌；给外壳、阅读面、浮层三个职责明确的层。不要用 `.shell > *` 统一改定位，避免重演链路浮层挤主界面的问题。
4. 外观页增加“透明/磨砂强度”“减少透明度”“恢复预设”与浅/深预览；调参先走现有草稿，不自动保存其它未确认设置。
5. 先做 Windows 浅/深、Apple 浅/深四套基线，再做可选 Desktop Acrylic / Glass 变体。每阶段独立提交，可以回退。

## 验证矩阵

| 项目 | 验收 |
|---|---|
| 场景 | 首页、歌曲列表、详情、队列、链路、DSP、设置都遵守同一套层级 |
| 尺寸 | 1440、1050、920、720 宽度；长歌名、长专辑、中文英文混排不覆盖控件 |
| 可访问性 | 深浅色、失焦、高对比、减少动画、减少透明度、键盘焦点均可辨认 |
| 性能 | 原生背板只一层；模糊尽量局部；不对频谱/整页每帧做 backdrop-filter；隐藏页面停止可视化请求 |
| 状态 | 切预设不丢队列顺序、播放进度、当前歌词、详情主题；预览取消能还原 |
| 准确性 | FFT 带高频显示补偿时标为相对幅值；瞬时 RMS 不冒充 LUFS/动态范围；取不到数据明确说明 |

## ECHO 是否已经有详情可视化

有。本机 `ECHO-main/src/renderer/pages/LyricsPage.tsx` 的 `lyrics-music-reactive-layer` 包含 wash 和 12 条 spectrum，并受 `lyricsMusicReactiveVisualsEnabled` 与性能策略控制；实现位于约 2744 与 5795 行。本机 Twilight 的 `AudioVisualizerPanel.vue` 则桥接 `resources/audio-visualizer/index.html`，以 50ms 间隔请求可视化帧。两者不是同一页面：前者是歌词氛围，后者就是本次截图的音频仪表。

本轮 Celeste 用自己的 DOM/SVG 实现仪表主题，复用现有 FFT 和采样接口，不引入 Vue/Electron，也不加载外部播放器或改音频处理链。没有直接复制外部页面的运行脚本。
