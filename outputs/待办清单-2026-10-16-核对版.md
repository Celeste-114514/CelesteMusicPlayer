## 二点五、第三轮（10-16 深夜）实际改了什么

| 你提的问题 | 怎么改的 |
|---|---|
| 收起态图标还是没有在窄条里水平居中 | 根因：上一版为了"跟汉堡对齐"给整行加了 Margin 偏移，把**图标在按钮里的居中**破坏了——汉堡对齐了，图标歪了。改成两件事分开：图标两态都**恒为 Center**（`NavContentAlignment` 单一真相源），汉堡按实测值追图标 + 可右调 2px 的常量 |
| 进度条和按钮快速抖动 | 根因：布局校正挂在 `LayoutUpdated` 上，每次布局落定都同步改 Margin → 改完又触发布局 → 来回抖（还差点引发 LayoutCycleException）。改成**只在内容尺寸变化时校正一次**（SizeChanged），配 0.5px 阈值 |
| 展开收起图标还是一闪 | 真凶不是重建图标，是**收起动画把整块卡片滑出窗口左缘**，图标在卡片左侧 22px 处，跟着被裁掉，动画结束列宽突变又弹回。改成"底板滑、内容反向补偿"，图标全程钉在原地 |
| 播放栏「喜欢」心形按钮挪到左侧 | 挪到按钮排最左（进度条是按播放按钮实测定位的，挪顺序不影响它） |
| 选择框只能选一首 | 前两版全败后挖到真根因：**DataGrid 的行选中挂在 `Tapped` 上（`AddHandler(handledEventsToo:true)`，子元素拦不住），且对交互式子元素没有任何豁免**——点复选框时 Click 先跑、Tapped 随后到，把焦点行改成当前行，多选被冲成单选（v2 在 Click 里恢复快照也被这一步冲掉）。第三版定案：DataGrid 退化成只管焦点行（SelectionMode=Single），多选自管 `_checkedSet`，外加一个「指针按下哨兵」——本手势从复选框发起时，无视它连带来的所有 SelectionChanged |
| 选中背景是方方正正的矩形，难看 | 根因也找到了：行模板选中底是 `Rectangle x:Name="BackgroundRectangle"`，Fill 绑主题资源、选中态动画直接写 `(Fill).(SolidColorBrush.Color)`——**在行上设 `row.Background` 完全无效**（前两版都白设了）。有效杠杆是四个 `DataGridRowSelected*BackgroundColor/Opacity` 主题资源。改成主面板同款半透明灰（深色=白23% / 浅色=灰16%），圆角用 Rectangle 自带的 RadiusX/RadiusY=4 实现（不用抄整套模板），不要左竖条、文字不反白 |
| 歌曲列表每首歌封面糊（参考 ECHO） | **分档预生成 + 磁盘缓存**落地：`CoverArtService.cs`，三档 96/320/768，键=源图字节 sha256（换图自动失效），只缩不放，有界并发 8。列表小图走 96 档、歌单墙/专辑墙走 320 档；缓存命中零 TagLib 零解码 |
| 标签页读取慢（参考 Kid3） | **懒解析**落地：`BuildEntry` 改 `ReadStyle.None` 只读标签帧（时长/码率/采样率全不读——这些要扫音频帧，MP3 还得遍历全部帧头）；扫描结束后 `EnrichAudioFactsAsync` 用完整 ReadStyle 后台补算（并发 4），**每条补完立刻亮一条**，不是干等全部读完。列表瞬间可读，音频信息随后陆续齐 |

**顺带纠正**：你说"WebDAV 早就做好了"——对，是我这边 10-15 D3 审计脚本抓不到动态内容误判成"没做过"，
实际 `PlaylistItem.RemotePath` / WebDAV 设置分类都在，功能是完整的。这条从待办里划掉。

## 七点五、标签页读取慢 + 封面糊 —— ✅ 已按 Kid3 / ECHO 的路子落地（第三轮）

**原来慢的原因**：每个文件 `TagLib.File.Create(path)` 全量解析——TagLib 默认连音频属性一起算，
`Properties.Duration` 对 MP3 要遍历全部帧头；`TryGetFactsFast` 发现码率缺口还会起 ffmpeg 子进程。
单首约 30ms，且随文件数线性涨。

**落地内容**：

| 参考对象 | 借了什么 | 落在哪 |
|---|---|---|
| **Kid3** | 只解析标签帧，音频属性 lazy | `BuildEntry` 改 `TagLib.ReadStyle.None`；时长/码率/采样率改由 `EnrichAudioFactsAsync` 扫描后后台补算（并发 4，补一条亮一条，新一批到达取消上一批） |
| **ECHO** | 封面三档预生成 + 磁盘缓存 | `CoverArtService.cs`：96（列表）/ 320（歌单墙专辑墙）/ 768（大图）三档；键=源图字节 sha256；只缩不放；有界并发 8；`.tmp` 原子替换 |

**默认列的处理**（你说"默认显示的列要改一下"）：时长/码率/采样率列**保留显示**，但扫描瞬间是空的，
补算线程陆续填上——你看到的应该是"列表先出来，数字随后跳齐"，而不是卡住不动。
如果你更想要"默认干脆不显示这几列、用到再勾"，在「列…」里取消勾选即可，说一声我也可以把默认勾选改掉。

**还剩的小尾巴**：曲库导入侧（不是标签页）仍是老路径，导入 4000 首时慢的问题没动——那个要单独排。

## 八点五、BiliPai 动效专节（2026-10-16 你点名要的，排在令牌化后面）

参考代码在 `C:\Users\MSI\Downloads\ABDM\BiliPai-main`（安卓 / Jetpack Compose）。你说"它的动效什么的我真的很喜欢，我也想做进我的播放器"——**搬的是动效语言，不是它的功能**。逐条对照后的落地清单：

| BiliPai 里的做法 | 我们的 WinUI3 对应物 | 落到哪 |
|---|---|---|
| 页面转场（导航时整页滑入滑出 + 共享元素过渡） | `ConnectedAnimation`（Frame/NavigationView 自带共享元素转场） | 板块切换 / 标签页六个子页互切 |
| 列表项依次入场的错落动画（staggered） | 列表 `ItemContainerTransitions` + 延迟递进（`Composition` 或 `TransitionCollection`） | 歌曲列表 / 专辑墙首屏加载 |
| 点按反馈（按下去缩小、抬起来弹回） | `PointerPressedThemeAnimation` / 缩放微动画（`ScaleTransform` + 80~120ms） | 所有可点卡片、按钮 |
| 显隐动画（`AnimatedVisibility`：展开收起带高度+透明度过渡） | `ImplicitAnimation`（Composition 隐式动画，元素出现/消失自动补间） | 左栏展开收起、设置分组折叠、快速编辑多选卡 |
| 呼吸 / 循环动效（`rememberInfiniteTransition`） | `Storyboard` 循环动画（已有先例：项目里 new Storyboard + SetTarget 可用） | 播放页唱片旋转、频谱条 |
| Lottie 矢量动画资源 | WinUI3 无 Lottie 运行时；等价物 = `AnimatedVisualPlayer`（Lottie 源可直接放）或 SVG 路径动画 | 空状态插图、加载中指示 |

**动手前的两个前提**：① 等 UI 令牌化收尾（你定的顺序）；② 动效统一走「先写终态、动画 From→终态播过去」的本项目铁律，`Begin()` 抛异常也不能停在半死状态。
